## 知识点整理

### 1. this 指针

**this 是成员函数（非静态）里的隐藏指针参数，指向调用该函数的那个对象**。

```cpp
class A {
public:
    int v;
    A(int v) { this->v = v; }   // this->v 是成员，v 是形参（重名区分）
    A& GetObj() { return *this; } // *this 就是对象自身
};
```

要点：

- **this 是隐式的**：`a.f()` 编译后等价于 `f(&a)`，函数内 `this` 就是 `&a`
- **不占对象内存**：this 是函数参数，不是对象的成员，`sizeof(A)` 不含它
- **主要用途**：
  - 成员与形参重名时区分：`this->v = v;`
  - 返回 `*this` 实现链式操作（mooc010）：`a.GetObj() = m;`
  - 把自身地址传出去（mooc012）
- **const 成员函数里 this 是 `const A*`**：通过 this 只能读，不能改成员。此时想返回自身指针要写成 `const A*`：

```cpp
const A* getPointer() const { return this; }
// this 的类型是 const A*，返回类型必须匹配，否则编译报错
```

> ⚠️ **静态成员函数没有 this**（下面讲），因为它们不属于任何对象。

### 2. 静态成员变量（static member）

**`static` 修饰的成员变量属于"类"本身，不属于任何对象，所有对象共享同一份**。

```cpp
class A {
public:
    static int count;   // 类内只声明
    A() { count++; }
};

int A::count = 0;       // ★ 必须在类外定义并初始化（唯一一份）
```

要点：

- **类内声明、类外定义**：`int A::count = 0;` 必须写在类外（C++11 之前），否则链接错误
- **访问方式**：`A::count`（类名）或 `a.count`（对象）都可以
- **不占对象空间**：静态成员存在全局区，`sizeof(A)` 不含它
- **静态成员函数**：
  - 用 `static` 修饰，**没有 this 指针**
  - 只能访问静态成员，不能访问非静态成员（没有对象可指）
  - 调用：`A::func()` 或 `a.func()`
- **与全局变量的区别**：静态成员在类的作用域内、有访问权限控制（private 静态成员外部不可见）

### 3. 成员对象与封闭类（mooc011）

**成员对象**：一个类的成员变量是另一个类的对象。
**封闭类（enclosing class）**：含有成员对象的类。

```cpp
class Base {
public:
    int k;
    Base(int n) : k(n) { }
};

class Big {              // 封闭类
public:
    int v;
    Base b;              // 成员对象（没有默认构造！）
    Big(int n) : v(n), b(n) { }   // ★ 必须在初始化列表里给 b 传参
};
```

要点：

- **初始化列表是给成员对象传参的唯一途径**：`b` 没有默认构造，`Big(int n){ b = Base(n); }` 这种赋值写法在进入函数体前就会编译报错（因为 `b` 在函数体执行前就要构造）
- **构造顺序：先成员对象、后封闭类自身**（按成员声明顺序）
- **析构顺序相反：先封闭类自身、后成员对象**
- **默认拷贝构造会逐成员拷贝**：`Big a2 = a1;` 时 `a2.b` 会调用 `Base` 的拷贝构造——所以封闭类通常不需要自己写拷贝构造

### 4. 友元（friend）

**友元可以访问类的 private 成员**，声明在类内部，用 `friend` 关键字：

```cpp
class A {
private:
    int secret;
public:
    A(int s) : secret(s) { }
    friend void show(A &a);      // 友元函数：可以访问 a.secret
    friend class B;              // 友元类：B 的所有成员函数都能访问 A 的私有成员
};

void show(A &a) {
    cout << a.secret;            // ✅ 友元可以读私有成员
}
```

要点：

- **友元不是成员函数**：没有 this，不受访问权限控制（它在类外面）
- **单向性**：A 是 B 的友元 ≠ B 是 A 的友元（"我信任你"不代表"你信任我"）
- **适用场景**：重载 `<<`/`>>` 运算符时，运算符左操作数不是本类对象，需要友元才能访问私有成员
- ⚠️ 友元破坏了封装性，能用成员函数解决的尽量不要用友元

### 5. mooc013 魔兽世界之一：备战（综合练习）

**题目规则**（OJ 原文核对过）：

- 红方按 iceman→lion→wolf→ninja→dragon **循环**制造；蓝方按 lion→dragon→ninja→iceman→wolf 循环
- 每分钟双方各造一个士兵；造士兵消耗生命元
- **跳过规则**：生命元不足造当前类型 → 尝试下一种；**五种都不能造 → 才停止**（永久）
- 输出：`Case:n`、三位时间 `000`、士兵编号从 1 计、同分钟先红后蓝

**类设计**（三层的思路值得记住）：

```cpp
class Color {      // 颜色 → 决定制造顺序
    int soldierOrder[5];
};
class Soldier {    // 士兵：属性（编号/生命值/类型）
    int code, health; string type;
};
class Commander {  // 司令部：状态（生命元/各类型数量/总数/是否停止）+ 行为（制造）
    int health, s_num[5], s_sum;
    bool stop;
    void createSoldiers(int time);
};
```

**核心制造逻辑**（先判断、后制造）：

```cpp
void createSoldiers(int time) {
    if (stop) return;
    for (int i = 0; i < 5; i++) {
        int idx = order[(time + i) % 5];        // 从 time%5 开始循环尝试 5 种
        if (health >= typeHealth[idx]) {        // 先判断够不够
            health -= typeHealth[idx];          // 够才扣费
            ++s_sum;                            // 成功才编号、计数、输出
            cout << ...;
            return;
        }
    }
    stop = true;                                // 5 种都不行 → 停止
    cout << ... << " headquarter stops making warriors" << endl;
}
```

## 常见陷阱清单（今日踩坑汇总）

| # | 陷阱 | 现象 | 正确做法 |
| --- | --- | --- | --- |
| 1 | **C++11 类内初始化**（`int a[5] = {0};`、`int x = 0;`）| 本地正常，OJ 编译报错（老编译器只认 C++98）| 类内只声明，初始化挪进构造函数 |
| 2 | **编号在失败尝试时自增**（mooc013）| 跳过几次后士兵编号跳号 | 只在制造成功时才 `++s_sum` |
| 3 | **计数数组用错下标**（mooc013）| 打印 iceman 却给 wolf 计数 | 用"实际制造成功"的类型下标 |
| 4 | **`health == 0` 提前 return**（mooc013）| 生命元恰好花完时丢失停止信息 | 0 也要走"全失败→停止"逻辑 |
| 5 | **靠 health 的符号判断停止**（mooc013）| 停止后每轮重复输出停止信息 / 死循环 | 用独立的 `stop` 标志，与 health 解耦 |
| 6 | **"先制造后判断，失败再恢复"**（mooc013）| 副作用已发生（编号、计数被污染），恢复麻烦易错 | 先判断条件，成立再执行副作用 |
| 7 | **静态成员变量忘在类外定义** | 链接错误：undefined reference | `int A::count = 0;` 写在类外 |
| 8 | **成员对象没有默认构造、又没写初始化列表** | 编译报错：no matching constructor | 封闭类构造函数用初始化列表传参 |
| 9 | **const 成员函数里返回 `A*`** | 编译报错（this 是 `const A*`）| 返回类型也加 const |

## 调试经验

- **"本地能过样例 ≠ 提交正确"**，三种原因按概率排查：
  1. 逻辑 bug（本次：跳过规则、编号跳号、health==0）
  2. 提交的代码和本地不一致（改了没重新提交）
  3. 编译环境差异（本次最终原因：C++11 类内初始化在 OJ 老编译器上不通过）
- **用边界测试数据验证**：恰好吃完生命元（health 变 0）、开局造不了、一方先停另一方继续、多组数据、时间进到三位数以上——这些样例都不覆盖
- **状态机写法**：凡是"停止/结束/失败"这类状态，用独立的 bool 标志记录，不要靠数值符号（health < 0）判断——后者在状态持续期间会被反复触发
